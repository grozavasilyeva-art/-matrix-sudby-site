# Матрица судьбы: архитектура и порядок запуска

> Статус: проектирование и разработка, коммерческая оплата отключена.
> Этот документ хранится в публичном репозитории. **Никаких ключей, токенов, данных покупателей и платных текстов здесь быть не должно.**

## Архитектурные границы

1. **Публичный сайт:** обычные HTML/CSS/JS. Бесплатный калькулятор выполняет вычисления в браузере, не вызывая платные API.
2. **Публичная публикация:** результат команды `node scripts/build-static.mjs`, каталог `dist/`. Хостинг сменный: любой провайдер статических файлов с HTTPS. Никаких Netlify Functions, Cloudflare Workers или Yandex Functions в клиентском коде.
3. **Коммерческий backend:** отдельный Node.js-сервис с документированным HTTP API. Не используется бесплатным калькулятором.
4. **Платёжный адаптер:** интеграция с ЮKassa только с серверной стороны. Цена на сервере: 550.00 RUB; никогда не доверять цене из браузера.
5. **Заказы и отчёты:** российская инфраструктура, соответствующая применимым требованиям обработки персональных данных. Приватное хранилище и восстановимые резервные копии на независимой площадке.
6. **Доставка:** временная ссылка только для оплаченных заказов. При отказе backend не принимать новые оплаты и показать режим временной недоступности покупки, бесплатный калькулятор продолжает работать.

## Разработка не должна расходовать облачные квоты

- Ветви: `main` = публичная версия; `develop` = работа над следующей версией.
- PR: проверки Node.js без сетевых вызовов и сборка `dist/`; автоматическая публикация на production только после слияния по согласованной процедуре.
- Обычные тесты платежей используют фиктивный ответ провайдера без реальных списаний и без вызовов Yandex Cloud.
- Ни одна `push`-операция в `develop` не создаёт облачных ресурсов.
- Для реального размещения нужен отдельный и явно разрешённый секрет доступа к хостингу, хранимый в настройках CI, не в исходниках; предпочтительно краткосрочные учётные данные и минимальные права.
- Не публиковать платную библиотеку в GitHub-репозитории, client JS или статических артефактах.

## Защита от ботов и стоимости

Различать **человеческую аналитику** и **облачный биллинг**. Снятые аналитикой просмотры ботов могут всё равно быть оплачиваемыми HTTP-запросами на инфраструктуре.

1. Статическая выдача с кэшированием и неизменяемыми версиями; события расчёта матрицы без API.
2. Только коммерческие маршруты вызывают backend; ограничение частоты до запуска дорогих задач, при подозрении CAPTCHA и защита уровня периметра.
3. Заказы создаются с идемпотентностью; PDF генерируется только после независимой верификации подтверждённого платежа.
4. Учёт по маршрутам: публичные страницы, создание заказов, webhook, подтверждённые заказы, генерации PDF, боты/подозрительные запросы и реальные расходы. Не использовать IP как единственное доказательство ботности.
5. Алерты по **потреблению** (50%, 80%, 95% применимой бесплатной квоты), по **денежным расходам** и по **аномальному росту за час**. Проверять точные актуальные квоты, условия и метрики непосредственно у выбранного провайдера. Бюджетное уведомление не является жёстким стоп-лимитом.
6. Важные системные операции (подтверждения уже проведённых оплат, доступ к оплаченным PDF) не отключать тем же рубильником, который защищает необязательные публичные запросы.
7. Фиксировать допустимый месячный платный бюджет отдельно от бесплатных квот; никаких предположений «гарантированно 0 рублей» при публичной нагрузке.

## Резервирование без двойной ежемесячной аренды

- **Исходники** находятся в GitHub. Хранить у владельца периодические независимые копии исходников и сборки.
- **Бесплатный сайт:** переносимый набор статических файлов; заранее выбрать второй совместимый хостинг и протестировать восстановление и HTTPS.
- **DNS:** зарегистрированный на владельца домен и доступ к DNS-настройкам независимо от хостера; подготовить инструкции восстановления. DNS-переключение не мгновенно.
- **Коммерческий backend и база:** проверенные отдельные резервные копии и план восстановления; резервировать данные вне единственного поставщика.
- Не называть такую подготовленную копию «автоматическим failover». Автоматический переход требует дополнительного сервиса, проверки состояния и затрат.

## Минимальное API, которое будем разрабатывать после отчёта

- `GET /health` — доступность, без утечки секретов.
- `POST /orders` — валидация даты/контакта, rate limit, idempotency key, создание заказа; цена 550 ₽ на сервере.
- `POST /payments/webhook` — обработка уведомления + независимое получение платежа через API ЮKassa, проверка суммы, валюты, order ID и статуса; повторы безопасны.
- `GET /orders/:id` — статус по авторизованной временной ссылке, без раскрытия чужих заказов.
- `GET /orders/:id/report` — выдача временной приватной ссылки только после оплаты.
- Хранилище заказов с понятной политикой хранения/удаления, отдельное закрытое файловое хранилище.

## Немедленное правило

Пока пользователь не проверил новую среду, **Netlify и существующий публичный сайт остаются без изменений**. Новые поставщики и платёжные системы не подключаются без выбора владельца аккаунта и соответствующих разрешений.

## Прототип персонального PDF (редакционная проверка)

- Отдельно от публичного репозитория подготовлен **приватный** генератор на Python + ReportLab: 31 страница, 22 авторских описания арканов, восемь тематических глав, диаграмма и блок практик. Проверены даты 23.08.1989, 29.02.2000, 05.06.2001. Это **редакционная версия, не готовая к продажам**, её нельзя выкладывать в публичный репозиторий.
- Публичный модуль `server/report-job.mjs` содержит только интерфейс задания для будущего приватного исполнителя. `prepareReportJob(trustedOrder)` принимает исключительно проверенный заказ из доверенной БД после серверной проверки платежа, не объект из браузера.
- Платная библиотека находится только в отдельном приватном пакете. В CI публичного репозитория не нужно устанавливать этот пакет или выполнять генерацию полного отчёта, иначе секретные материалы могут попасть в сборочные журналы и артефакты.
- Закрытый сервер генератора ещё не развёрнут. ЮKassa не подключена, приватное хранилище и авторизованное скачивание ещё не реализованы.
