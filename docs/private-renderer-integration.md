# Приватный генератор PDF: реальное соединение с Node.js

**Текущий этап:** локальная интеграция без банковских переводов, веб-сервера и облачных затрат. Публичный сайт в main не меняется.

## Что проверено

- Архив `Matrix_Sudby_Private_Generator_V3.zip` содержит Python-генератор, редакционную библиотеку и обложку. Не добавлять этот архив или распакованные файлы в публичный GitHub.
- В `server/private-python-renderer.mjs` добавлен адаптер `createPrivatePythonRenderer`. Ему передают *путь к отдельному приватному пакету*.
- Адаптер проверяет формат задания и дату, запускает Python без shell, пишет PDF во временную закрытую директорию, ограничивает время выполнения и размер файла, проверяет маркеры PDF и удаляет временные файлы.
- На изолированной машине проверена реальная генерация двух разных дат: `1989-08-23`, `2000-02-29`; файлы корректно начинаются с PDF-сигнатуры, размер около 540 КБ.
- В GitHub Actions проходит тестовый пакет с фиктивным Python-генератором, без самого платного содержимого и без внешних API.

## Подключение через код (только сервер)

```js
import { createPrivatePythonRenderer } from './server/private-python-renderer.mjs';
import { createFulfillment } from './server/fulfillment.mjs';

const renderer = createPrivatePythonRenderer({
  bundleDir: process.env.PRIVATE_PDF_DIR,
  pythonBin: 'python3',
  timeoutMs: 45000
});

// В эту функцию передаются реальные закрытые адаптеры заказов,
// банка, авторизации и хранения, а НЕ объекты из браузера.
const fulfillment = createFulfillment({
  orders, provider, renderer, storage, authorize
});
```

Переменную `PRIVATE_PDF_DIR` задавать только в доверенном серверном окружении, не в публичных GitHub Secrets сборки сайта и не в HTML. На сервере должны быть установлены Python 3.10+, ReportLab 4.x и кириллические шрифты.

## Что ещё не готово

1. **Хостинг:** серверную среду и базу заказов не выбрали. В публичном облаке ничего не создано.
2. **Реальный платёж:** ЮKassa не подключена. Тесты с фиктивными платежами не означают готовность принимать деньги.
3. **Реальное хранение:** пока нет постоянной БД, атомарного claim с fencing-token, приватного Object Storage и доступных по HTTPS подписанных ссылок.
4. **Безопасность:** необходимы проверка webhook, rate limit до дорогих операций, правильная авторизация, журнал отказов, резервные копии, удаление персональных данных и ограничения расходов.
5. **Продукт:** платный отчёт V3 пока редакционный прототип. Не подключать кнопку покупки до проверки содержимого, юридических документов и пользовательских сценариев.

## Ближайший технический этап

Реализовать HTTP-слой и локальную БД для заказов в режиме тестовых операций, затем испытать путь «заказ → фиктивное подтверждение → реальный PDF → защищённое скачивание». Контролировать, чтобы тестовые endpoints не могли быть случайно опубликованы. После этого выбрать российский хостинг и ЮKassa в тестовом режиме.

**Принцип:** любой редактируемый файл должен оставаться переносимым между провайдерами; облачные вызовы не должны запускаться при обычных изменениях сайта.
